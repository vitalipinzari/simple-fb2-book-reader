# 02 — Repository, build system, versioning, release staging and code conventions

Scope: the complete file layout of the repository and where each file comes from, how the CMake/vcpkg build is
organised for Windows and Android, how the version flows into every artefact, how release folders are filled,
and the code conventions the implementation files must follow. All build files themselves are verbatim in
`ai/files/01-build-system.md` (Gradle files in `03-android-project.md`); this spec explains them so that the
whole fits together — never change those files.

## 2. Toolchain and dependencies

Versions: `ai/PROMPT.md` § 4. Windows needs only Visual Studio 2026 (or its Build Tools) with the *Desktop
development with C++* workload: it brings MSVC, CMake, Ninja, Git and vcpkg. `build.ps1` finds Visual Studio with
`vswhere -latest -prerelease -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64`, uses its
CMake and CTest, sets `VCPKG_ROOT` to `<VS>\VC\vcpkg` unless already set, and puts VS's Git on `PATH` (vcpkg needs
it to fetch the baseline). Android needs Android Studio (SDK, NDK 28.2.13676358, CMake 3.22.1, JBR) plus the same
vcpkg (spec 11).

Dependencies (vcpkg manifest `vcpkg.json`, `builtin-baseline 9a5dfef5d1a0438a7d24856a85bd60f309d355e9`):

| Port | Features | Platforms | Used for |
|---|---|---|---|
| `sdl3` | default | all | window, GL context, events, timers, dialogs, file I/O, main callbacks |
| `freetype` | `default-features: false` | all | glyph rasterisation |
| `harfbuzz` | `default-features: false` | `!android` | shaping (Android: `cmake/HarfBuzzAmalgamated.cmake`) |
| `imgui` | `sdl3-binding`, `opengl3-binding` | all | panels and bars |
| `glad` | `gl-api-41` | `!android` | OpenGL 4.1 core loader |
| `miniz` | default | all | zip archives |
| `nlohmann-json` | default | all | settings and metadata cache |
| `stb` | default | all | `stb_image` decoding, `stb_image_write` PNG (screenshots) |

Windows triplet `x64-windows-static-md` (static libraries, dynamic CRT), install tree `build/vcpkg_installed`
(both from `CMakePresets.json`). Android triplets `arm64-android` and `x64-android`, one install tree per ABI
under `build/vcpkg_android/<triplet>` (manifest mode holds one triplet per tree).

## 3. CMake structure (`CMakeLists.txt`, verbatim)

- `cmake_minimum_required(VERSION 3.22)` because Gradle uses the SDK's CMake 3.22.1; Windows uses VS's CMake.
- **Android prologue** (only when `ANDROID_ABI` is set, i.e. under Gradle): takes `VCPKG_ROOT` from the cache
  or environment, chain-loads the NDK toolchain through vcpkg's (`VCPKG_CHAINLOAD_TOOLCHAIN_FILE`), maps the ABI to
  the vcpkg triplet (`arm64-v8a`→`arm64-android`, `x86_64`→`x64-android`, `armeabi-v7a`→`arm-neon-android`,
  `x86`→`x86-android`), sets `VCPKG_INSTALLED_DIR` to `build/vcpkg_android/<triplet>` and exports
  `ANDROID_NDK_HOME` for vcpkg's triplets.
- **Version**: reads the first line of `VERSION` into `LL_VERSION` (a configure dependency), `project(Lanternleaf
  VERSION ${LL_VERSION} … LANGUAGES C CXX)`, `LL_DEVELOPER "Vitali Pinzari"`, `LL_COPYRIGHT_YEAR "2026"`,
  `configure_file(src/app/Version.h.in → build/<tree>/generated/app/Version.h @ONLY)`.
- C++20, no extensions. MSVC: `/utf-8 /W4 /permissive- /Zc:__cplusplus /MP /external:anglebrackets
  /external:W0`, definitions `NOMINMAX WIN32_LEAN_AND_MEAN _CRT_SECURE_NO_WARNINGS`.
- Options: `LL_BUILD_TESTS` (ON), `LL_BUILD_APP` (ON), `LL_BUILD_TEXT` (ON), `LL_STAGE_RELEASE` (ON).
- Targets:
  - `ll_core` (static): the twelve `src/core/*.cpp`; includes `src/` and stb; links `miniz::miniz`,
    `nlohmann_json::nlohmann_json`. No SDL, no GL.
  - `ll_text` (static, if `LL_BUILD_TEXT`): `src/text/*.cpp`; links `ll_core`, `Freetype::Freetype`,
    `harfbuzz::harfbuzz`.
  - `Lanternleaf` (if `LL_BUILD_APP`): `src/main.cpp`, `src/app/{App,AppUi,FileBrowser,Settings,Themes}.cpp`,
    `src/render/*.cpp`, `src/platform/Platform.cpp`. Windows: `WIN32` executable, the generated
    `lanternleaf.rc` (icon + VERSIONINFO), links `ll_text SDL3::SDL3 imgui::imgui glad::glad`, post-build copy of
    `assets/` next to the exe. Android: `SHARED` library named `main` (`libmain.so`), `LL_USE_GLES`, SDL3 static
    with `--whole-archive` (keeps its JNI entry points), links `ll_text SDL3::SDL3-static imgui::imgui GLESv3 EGL
    android log`; assets are packaged by Gradle.
  - `ll_tests` (if `LL_BUILD_TESTS`): `tests/core_tests.cpp`, links `ll_text` with `LL_TESTS_WITH_TEXT` (or
    `ll_core` alone when `LL_BUILD_TEXT` is OFF); CTest runs it with the source `assets` folder as argument.
  - `stage_release` (custom target, `ALL`, desktop only, if `LL_STAGE_RELEASE`): section 5.
- The build-time notices file `build/<tree>/THIRD-PARTY-NOTICES.txt` is written at configure time: a short
  header, then the vcpkg `share/<port>/copyright` file of each of `sdl3 freetype harfbuzz imgui glad miniz
  nlohmann-json stb`, each under `==================== <port> ====================`. It is staged next to the
  exe. (The shorter, hand-assembled `assets/licenses/THIRD-PARTY-NOTICES.txt` that the About panel shows is a
  verbatim file.)
- MSVC runtime DLLs: `InstallRequiredSystemLibraries` (with system-runtime install skipped and UCRT off) provides
  the list; `msvcp140.dll`, `vcruntime140.dll` and `vcruntime140_1.dll` are kept for staging, with a warning if
  none is found.

`CMakePresets.json` (verbatim): hidden `windows-base` (binary dir `build/${presetName}`, vcpkg toolchain from
`$env{VCPKG_ROOT}`, triplet, install dir; Windows hosts only), `vs2026` ("Visual Studio 2026 (x64)", generator
`Visual Studio 18 2026`, architecture x64) and `ninja` ("Ninja Multi-Config (from a VS Developer prompt)");
build presets `release`/`debug`, test preset `release` with output on failure. The Visual Studio build tree is
`build/vs2026/<Config>/Lanternleaf.exe` with `assets/` next to it.

## 4. Version

`VERSION` is the single source (`0.6.0`). It reaches:

| Where | How |
|---|---|
| `app/Version.h` | `LL_VERSION "0.6.0"`, `LL_VERSION_MAJOR/MINOR/PATCH`, `LL_DEVELOPER`, `LL_COPYRIGHT_YEAR`, `LL_COPYRIGHT "© 2026 Vitali Pinzari"` (the © is written as `\xC2\xA9`) |
| App | `kAppVersion = LL_VERSION`; About and Help panels; `SDL_SetAppMetadata` |
| Windows file properties | `FILEVERSION`/`PRODUCTVERSION 0,6,0,0`, `FileVersion`/`ProductVersion "0.6.0"`, `OriginalFilename "Lanternleaf-0.6.0.exe"`, `CompanyName "Vitali Pinzari"`, `LegalCopyright "Copyright (C) 2026 Vitali Pinzari. MIT License."` |
| Android | `versionName "0.6.0"`, `versionCode = major·10000 + minor·100 + patch` = 600 (Gradle reads `../VERSION`) |
| Release file names | `Lanternleaf-0.6.0.exe`, `Lanternleaf-0.6.0.apk` |

The project's habit (spec 14): bump `VERSION` for every delivered iteration; older release files stay next to
the new ones.

## 5. Release staging

- **Windows** — the `stage_release` target runs `cmake -DCONFIG=$<CONFIG> -DEXE=<exe> -DSTAGE_CONFIG=<generated
  stage_release_config.cmake> -P cmake/StageRelease.cmake` after every build of any configuration;
  `StageRelease.cmake` returns at once unless `CONFIG` is `Release`. It creates `release/Windows/`, copies the exe
  as `Lanternleaf-<version>.exe` (`ONLY_IF_DIFFERENT`; on failure — the staged exe is running — it prints the
  warning "release folder not updated: … Is that version still running? Close it and build again." and stops),
  copies the runtime DLLs, replaces `release/Windows/assets/` with a fresh copy of `assets/`, copies the
  build-time `THIRD-PARTY-NOTICES.txt`, and reports "Release build staged in …". Debug builds are never staged;
  `-DLL_STAGE_RELEASE=OFF` turns staging off. The folder is self-contained: copy it to any 64-bit Windows 10/11
  PC and run.
- **Android** — Gradle's `stageReleaseApk` task (finalizes `assembleRelease`) copies
  `app/build/outputs/apk/release/*.apk` to `release/Android/Lanternleaf-<version>.apk`.

Expected `release/` after a full build of the copy:

```
release/Windows/  Lanternleaf-0.6.0.exe, assets/ (fonts, hyphenation, licenses), msvcp140.dll,
                  vcruntime140.dll, vcruntime140_1.dll, THIRD-PARTY-NOTICES.txt
release/Android/  Lanternleaf-0.6.0.apk   (arm64-v8a + x86_64, signed with your release key)
```

## 6. Build scripts (verbatim)

`build.ps1 [-Config Release|Debug|RelWithDebInfo] [-Test] [-Run] [-Clean] [-CMakeArgs <string[]>]`: configures
with `cmake --preset vs2026 @CMakeArgs`, builds `build/vs2026` with `--parallel`, optionally runs CTest with
`--output-on-failure`, prints the exe path (and the release folder for Release builds), optionally starts the exe.
Native tools run through `Invoke-Tool`, which lowers `$ErrorActionPreference` to `Continue` while the tool runs
(Windows PowerShell 5.1 turns stderr output into terminating errors) and judges success by `$LASTEXITCODE`. The
first configure builds all vcpkg dependencies (≈7 minutes); later runs use vcpkg's binary cache.

`build-android.ps1`: spec 11.

## 7. Code conventions for the implementation files

The verbatim files show the style; the `.cpp` files you write must match it.

- C++20, namespace `ll` (sub-namespaces `ll::platform`, `ll::ui`, `ll::gl`); file-local helpers in an anonymous
  namespace at the top of the `.cpp`. No exceptions cross module boundaries: functions return `bool` / values and
  take an optional `std::string* err`; parsers never throw.
- Formatting: 2-space indent, no tabs, lines ≤ 120 columns, Google-like layout (braces on the same line,
  `public:`/`private:` indented one space, `}  // namespace ll` with two spaces before the comment, short bodies
  on one line where they fit, `if (x) return y;` without braces for one-liners).
- Naming: types `UpperCamelCase`; functions, methods and locals `lowerCamelCase`; data members end with `_`
  (`layout_`, `fontPx_`); struct fields without suffix; constants `kName`; macros `LL_*`; enums `enum class`
  (`BlockType::Paragraph`) except the bit-flag enums of the headers (`kSpanItalic`).
- Includes: the file's own header first, a blank line, library/system headers in angle brackets, a blank line,
  project headers as `"core/…"`, `"text/…"`, `"render/…"`, `"platform/…"`, `"app/…"`; alphabetical within each
  group.
- A header starts with `// Lanternleaf - <what it is>.` A `.cpp` starts with its include block (a leading comment
  only where the file needs an explanation, e.g. FileBrowser.cpp). `App.cpp` groups its sections between
  separator lines of `// ` followed by 93 dashes (96 characters), with a one-line `// Title` between them.
- Comments are complete English sentences that explain *why*; British spelling in comments and UI texts
  (colour, licence (noun), recognise, centre).
- Strings: UTF-8 everywhere (`/utf-8`), paths as UTF-8 `std::string`, converted to `std::filesystem::path` only
  through `pathFromUtf8` / `pathToUtf8`. Escapes such as `"\xC2\xA9"` only where a spec shows them.
- Performance rules the specs rely on: no work while idle (the main loop sleeps), shaping cached per string and
  style in em units, layout cached per block, background work in small time slices or on the search thread.
